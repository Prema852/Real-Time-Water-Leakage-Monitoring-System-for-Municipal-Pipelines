# AquaGuard – Real-Time Water Leakage Monitoring System

AquaGuard is an ESP32-based real-time water leakage monitoring system designed for pipeline applications. The system uses two YF-S201 flow sensors to compare the inlet and outlet flow rates. If the difference between the two flow rates reaches the defined critical level and remains there for a specified time, the system activates an alarm and automatically closes the water valve.

## Project Overview

Water leakage in pipelines can lead to significant water loss and may be difficult to detect manually, especially in long or concealed pipeline sections. AquaGuard provides a simple embedded-system approach to continuously compare water flow at two points in a pipeline.

The system measures the inlet flow using Flow Sensor 1 and the outlet flow using Flow Sensor 2. The ESP32 processes the sensor readings, applies calibration and averaging, calculates the percentage of flow loss, and determines whether the system is in a NORMAL or CRITICAL condition.

When a critical leakage is confirmed, AquaGuard:

- Turns ON the red LED
- Activates the buzzer
- Closes the water valve
- Latches the critical condition
- Displays the critical status on the LCD

The system can be reset using the push button connected to GPIO 4.

## System States

### NORMAL

When the calculated flow loss is below the critical threshold:

- White LED is ON
- Red LED is OFF
- Buzzer is OFF
- Valve is OPEN
- LCD displays `NORM`

### CRITICAL

When the calculated flow loss reaches or exceeds 15% for 3 consecutive seconds:

- White LED is OFF
- Red LED is ON
- Buzzer is ON
- Valve is CLOSED
- LCD displays `CRIT`
- Critical condition is latched
- Manual reset is required

## Working Principle

AquaGuard uses two flow sensors installed at different points of the pipeline.

```text
Water Supply
     |
     v
Flow Sensor 1
(Inlet)
     |
     v
Pipeline
     |
     v
Flow Sensor 2
(Outlet)
     |
     v
ESP32
```

The ESP32 counts the pulses generated by both flow sensors.

For the YF-S201 flow sensor, the code uses:

```text
Flow Rate (L/min) = Frequency / 7.5
```

The Flow Sensor 2 reading is then corrected using a calibration factor:

```text
S2_CAL = 1.30
```

The system averages the sensor readings over the previous 5 seconds to obtain more stable values.

The percentage of flow loss is calculated as:

```text
Loss % = |Flow 1 - Flow 2| / Higher Flow × 100
```

If the calculated loss is:

```text
Loss < 15%
```

the system remains in NORMAL condition.

If:

```text
Loss >= 15%
```

the system considers it a possible critical leakage.

The critical condition must continue for 3 consecutive seconds before the valve is closed.

## Flow Sensor Processing

Both flow sensors use interrupt-based pulse counting.

The ESP32 counts the pulses generated by each sensor and calculates the pulse frequency.

The code uses:

```text
Flow Rate (L/min) = Frequency / 7.5
```

Flow Sensor 2 is corrected using:

```text
Corrected Flow 2 = Raw Flow 2 × 1.30
```

The corrected values are then used for the leakage calculation.

---

## Flow Averaging

The system stores flow pulse information from the previous 5 seconds.

This averaging helps provide more stable flow readings instead of relying on a single one-second measurement.

```text
Sensor Reading
      ↓
Pulse Count
      ↓
Flow Calculation
      ↓
5-Second Average
      ↓
Leakage Calculation
```

---

## Critical Leakage Confirmation

AquaGuard does not immediately close the valve when one reading reaches the threshold.

The system first checks whether the critical condition continues.

```text
Loss >= 15%
      ↓
Possible Critical Leakage
      ↓
Confirm for 3 seconds
      ↓
Critical State
      ↓
Valve Closed
```

This helps reduce false triggering caused by temporary flow fluctuations.

---

## Critical State Latching

The critical condition is latched after confirmation.

This is important because closing the valve causes the flow through the sensors to drop.

Without latching, the system could see the zero-flow condition and incorrectly decide that the pipeline is NORMAL.

Therefore:

```text
CRITICAL
   ↓
Valve CLOSED
   ↓
Critical State Remains Latched
   ↓
Manual Reset Required
```

The reset button connected to GPIO 4 clears the critical latch.

## Noise Filtering

The flow sensor pulse interrupt includes a minimum pulse-gap filter:

```cpp

```

Pulses that occur too close together are ignored to reduce the effect of unwanted noise or false pulses.

## Conclusion

AquaGuard is a simple ESP32-based real-time water leakage monitoring system that detects significant flow loss by comparing inlet and outlet flow rates.

The system uses two flow sensors, an ESP32, an LCD, LEDs, a buzzer, a relay, and a solenoid valve.

The ESP32 calculates the flow rates, applies calibration to the second sensor, averages the readings, and calculates the percentage of flow loss.

When the flow loss reaches or exceeds 15% and remains at the critical level for 3 consecutive seconds, the system enters the CRITICAL state. The red LED and buzzer are activated, and the relay closes the water valve.

The critical state remains latched until the reset button is pressed, preventing the valve from reopening automatically after a critical leakage event.

This prototype demonstrates a practical approach to real-time water leakage detection and automatic protection using an ESP32-based embedded system.
